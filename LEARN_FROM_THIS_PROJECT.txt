You shipped a real system: voice UI + AI chat + local Windows agent + optional
Web3 + tray host. Below is everything worth studying, in order of payoff.


--------------------------------------------------------------------------------
1. THE BIG IDEA (product architecture)
--------------------------------------------------------------------------------

Learn this first — it is the hiring story:

  Browser alone CANNOT control your laptop.
  So you split into layers:

  [ Voice / UI ]  →  Next.js web app (apps/web)
  [ Brain ]       →  LLM API routes (Gemini / OpenAI via Vercel AI SDK)
  [ Hands ]       →  Desktop agent on 127.0.0.1:3847 (apps/desktop-agent)
  [ Shell ]       →  Electron tray host (apps/host) starts both + tray icon

Keywords to master:
  - localhost / loopback (127.0.0.1)
  - client vs server
  - allowlist vs full system access
  - wake phrase / standby state machine
  - confirm-gated risky actions

Why companies care:
  You did not “make a chatbot webpage.” You designed a local agent with safety
  boundaries. That is systems thinking.

5. LOCAL ACTIONS PIPELINE (how the laptop gets controlled)
--------------------------------------------------------------------------------

Study files:
  - apps/web/src/lib/localActions.ts
  - apps/desktop-agent/src/server.js

Flow to memorize:

  User says “Open Chrome”
    → parseLocalAction() maps NL → { kind, target }
    → fetch http://127.0.0.1:3847/execute
    → Express agent runs Windows cmd (start chrome, explorer, etc.)
    → UI speaks/shows result

Learn:
  - Express HTTP API design (GET /health, POST /execute)
  - CORS for local UI → local agent
  - Binding to 127.0.0.1 only (security: not exposed to LAN/internet)
  - child_process exec / cmd /c on Windows
  - Allowlists (APP_MAP) vs open-ended shell
  - confirm:true for risky kinds (shell / kill)
  - Deny-lists for destructive patterns

Practice:
  Add one new app to APP_MAP + APP_ALIASES end-to-end.
  That single exercise teaches the whole pipeline.

9. SECURITY MODEL (say this in interviews)
--------------------------------------------------------------------------------

You should be able to explain:

  1. Agent listens only on 127.0.0.1
  2. Actions are allowlisted (known apps / folders / URLs)
  3. Risky shell needs explicit confirm
  4. Dangerous command patterns are blocked
  5. Browser cannot bypass the agent
  6. API keys stay server-side
  7. Wallet signing stays in the user’s wallet

This is the difference between a toy and a responsible agent.

12. GLOSSARY (own these words)
--------------------------------------------------------------------------------

  Monorepo          Multiple packages in one git repo
  Workspace         pnpm/npm linking between packages
  App Router        Next.js file-based routing under app/
  API route         Server endpoint in Next.js
  SSR / CSR         Server vs client rendering
  Loopback          127.0.0.1 — this machine only
  Allowlist         Only permitted actions run
  STT / TTS         Speech-to-text / text-to-speech
  LLM               Large language model
  Tool calling      Model returns structured function calls
  Intent            Structured action request
  Electron          Desktop shell around web tech
  System tray       Always-on icon in Windows notification area
  wagmi / viem      Ethereum wallet + RPC libraries
  CORS              Cross-origin rules for browser fetch
